## Blocker

### QA-015: Online pickup orders can never be handed off, so they can't be completed or paid
- **Area:** dashboard
- **URL:** `/dashboard/platform/orders/cmvlnst0y001uoh018qs00tdm` (`RXO-MVLNST0G-DCE628`)
- **Steps:**
  1. Place a storefront pickup order with "Pay at pickup".
  2. In the dashboard, open the order. **Next status** offers `ready`. Record it: "Fulfillment advanced to server status ready."
  3. **Next status** now offers `handed off`. Fill in the reason, tick the attestation and click **Record transition**.
- **Expected:** The order is handed off and the pay-at-pickup payment is collected. That is how every pickup order ends.
- **Actual:**
  - The page shows a red `Minified React error #441…` and the server action returns 500. Retrying gives the same result.
  - The order stays at **Ready**, payment **pending**, forever. The guest's tracking page never reaches "Picked up".
  - **Cause:** `fulfillmentWorkflows.ts:35` requires `fulfillment.assignedTo` to be the current user. `assignedTo` is only set when a fulfillment moves *to* `preparing` (`:64`). Storefront orders are created already `preparing`, so `assignedTo` stays `null`. Live data: both online fulfillments have `assignedTo: null`. The POS/Rx order is assigned to `qa@openship.org`.
  - The order page has no "assign to me" control, so staff can't work around it.
- **Likely files:**
  - `features/keystone/mutations/fulfillmentWorkflows.ts:35,64`
  - `features/keystone/mutations/submitPharmacyOrder.ts` (initial fulfillment status and assignee)
  - `features/platform/orders/components/*` (no assignment UI)

## Major

### QA-016: Dashboard workflow errors show "Minified React error #441" or nothing at all, never the real reason
- **Area:** dashboard
- **URLs:** `/dashboard/platform/credentials`, `/dashboard/platform/prescriptions/[id]`, `/dashboard/platform/orders/[id]`, generic `/dashboard/<list>/create`
- **Steps (each one reproduced live):**
  1. On a fresh install, open **Credential review**. The **Fill policy** panel shows `Minified React error #441…` until a staff credential review exists. The real cause is the `pharmacist: true` membership check in `pharmacyFillPolicy`.
  2. **Record prescriber review** for an onboarding-seeded prescriber. The server returns 500 and the page shows no message. The real cause is "Prescriber with a valid NPI is required".
  3. **Authorize dispensing stage** after a safety review that was recorded before the fill reservation: `Minified React error #441` (QA-021).
  4. Order handoff (QA-015): `Minified React error #441`.
  5. Generic **Create Product** with Handle empty: nothing happens. With no drug reference: "Unable to complete the request. Please try again."
  6. Generic **Create Drug Reference** with Controlled Schedule set: the same generic message (QA-022).
- **Expected:** The operator sees the domain message the server already has ("Pharmacist credential review required", "Prescriber needs a valid NPI", "Payment must be captured before handoff"…).
- **Actual:**
  - Resolvers `throw new Error(...)`. GraphQL Yoga masks every non-`GraphQLError` in production as `Unexpected error.` (`INTERNAL_SERVER_ERROR`).
  - The platform server actions then throw, and Next replaces the message with React #441.
  - Generic forms replace all errors with `PUBLIC_REQUEST_ERROR` (`features/dashboard/lib/security.ts`, which is parity-locked with E-commerce), or return silently on `invalidFields`.
  - For a compliance-heavy workflow, the merchant can't tell what's missing. I needed the source code to finish the main workflow.
- **Likely files:**
  - `features/keystone/mutations/{fillWorkflows,credentialWorkflows,prescriptionWorkflows,fulfillmentWorkflows}.ts`: throw `GraphQLError` with a safe code, as `prescriptionRequests.ts` already does ("Sign in to send a request." comes through as `BAD_USER_INPUT`).
  - `features/platform/*/actions/*.ts`: return `{ error }` instead of throwing.
  - `features/platform/prescriptions/components/FillPolicySetup.tsx:15` (renders `cause.message`).
  - `features/dashboard/screens/CreatePage/CreatePageClient.tsx:62` (silent return).
